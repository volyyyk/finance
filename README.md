# FinApp — личные финансы

Локальное PWA-приложение для учёта счетов, вкладов, инвестиций, обязательств и кешбэка.

## Данные и приватность

- Основные данные хранятся в `localStorage` браузера на текущем устройстве.
- Приложение не синхронизирует данные между устройствами и не отправляет финансовую информацию на собственный сервер.
- Котировки, история и график выплат облигаций берутся из официального MOEX ISS. Запросы явно фиксируют `iss.json=compact` и `iss.version=on`; парсер принимает compact/extended block layouts и сообщает, если блок или JSON имеет неожиданную структуру. При HTTP-ошибках Worker сохраняет upstream status и диагностическое тело ответа.
- Альтернативный поставщик котировок можно подключить отдельно: официальный Finam Trade API предоставляет endpoint последней котировки, но требует API-токен и JWT-сессию. Секрет нельзя хранить в открытом PWA/localStorage; безопасная интеграция должна выполняться серверным Worker с секретом в настройках окружения. Пока такой резервный источник не включён, чтобы не выдавать неподтверждённые или неполные котировки за данные биржи. Без настройки используется прямой ISS с двумя резервными CORS-каналами; для устойчивой работы можно развернуть собственный Cloudflare Worker из `worker/moex-proxy.js`. Worker передаёт только публичный URL ISS и не получает данные портфеля.
- Worker — узкий прокси только для GET-запросов к фиксированному домену `iss.moex.com`, не универсальный прокси. В приложении откройте **Настройки → Сервер котировок MOEX**, вставьте HTTPS-адрес Worker и нажмите «Проверить и сохранить». Адрес хранится локально на устройстве и не входит в резервную копию.
- Развёртывание: Cloudflare Dashboard → Workers & Pages → Create → Worker → Deploy → Edit code; вставьте содержимое `worker/moex-proxy.js`, сохраните и скопируйте адрес вида `https://имя.workers.dev`. Затем добавьте его в настройки FinApp. Это одноразовая настройка; собственный Cloudflare-аккаунт нужен пользователю.
- Не подменяйте цену закрытия текущей котировкой. Если MOEX недоступна, приложение сохраняет последнюю известную цену и сообщает об ошибке; график купонов и погашений строится по опубликованным данным MOEX.
- Очистка данных браузера может удалить локальную базу. Регулярно создавайте резервные копии.

## Резервная копия

В меню **Настройки → Полная резервная копия** скачивается JSON-файл, содержащий все ключи приложения с префиксом `fin_`: продукты, операции, кешбэк, справочники, цели, зафиксированные результаты и настройки.

Импорт:
1. Сначала сохраните текущую резервную копию.
2. Выберите JSON-файл через **Настройки → Импорт**.
3. Проверьте предупреждение о замене данных и подтвердите импорт.

Новый формат содержит версию схемы и дату экспорта. Перед восстановлением проверяются формат, типы продуктов, идентификаторы и структура основных разделов. Некорректный файл не должен заменять текущие данные. Старые резервные копии в формате массива продуктов также поддерживаются: они восстанавливают только список продуктов, не затрагивая кешбэк и остальные разделы.

## Разработка и тесты

Сборка не требуется. Для проверки логики установите Node.js и выполните:

```bash
npm test
```

Приложение публикуется как статический сайт и может быть установлено как PWA. Для переноса данных между устройствами используйте экспорт и импорт JSON.
